# 面坊 · Noodle Factory

面条工厂后台 + 客户订货门户。Vite + React + Supabase（与 order-app / 配方 app 共用同一个 Supabase，表都在独立的 `noodle` schema 里，不动现有数据）。

界面：Magyar（默认）/ English / 中文

网址：**https://noodle.101bistro.hu**（Vercel，DNS 在 MagyarHosting 用 CNAME 指向 Vercel；旧地址 noodle-factory-gamma.vercel.app 仍可用）。Supabase → Authentication → Redirect URLs 需包含 `https://noodle.101bistro.hu/**`。

## 功能

| 模块 | 做什么 |
|---|---|
| 今日 | 待确认订单、待开通账号、今天送货、明天订单、待生产批次、在途进货；明天的生产计划（要做几批、原料够不够）、原料不足（按供应商、建议进货量）、快过期/已过期的原料批号 |
| 订单 | 默认显示全部订单（最新下单的在前，最多 500 张），可选只看某个送货日之后； 看全部订单，确认 → 备好 → 送达；可代客户下单 |
| 生产 | 按交货日汇总订单需求 − 现有库存 − 已排生产 = 需生产，自动建议批数；检查原料够不够；完成生产自动扣原料、加成品、生成批号 |
| 送货 | 新建送货：选客户自动带出地址、电话、联系人、送货备注，选货品时能看到库存；按送货趟（司机/车辆）分组，装车清单；确认送达时可改实送数量、填签收人、拍照上传签收凭证（只给内部看，可下载）；按实送数量自动扣成品库存；打印单张或整趟送货单（只给外部客户；固定匈牙利语；抬头为公司名、地址、税号、注册号、电话；每个产品下列出过敏原和储存条件；不显示价格；数量加粗并有合计）；自家餐厅不打送货单，改打出货标签（标签机，跟其他标签同尺寸：店名、单号、日期、送货趟、各产品数量和合计；每单、每趟或当天全部内部订单都能打）；到货当天起餐厅在点单 app 顶部「待收货」点「确认收货」即算送达（按订购数量扣库存，签收人记为该账号名） |
| 库存 | 原料/成品现有量、最低库存提醒、盘点、报损、完整出入库记录；原料按批号管理：收货生成批号（没填就用 P+进货单号），生产时按「最早到期先用」自动扣，过期批号不会被自动用掉；每个原料可展开看各批号剩余和到期日；原料最低库存默认「自动」= 近 4 周平均每周生产用量（历史不满 4 周按实际周数，至少按 1 周算；用量小的原料提到至少一包，但不超过 4 周用量；原料页可改成手动填写），低于它就提醒，进货建议补到约两周的量 |
| 进货 | 可互换的原料（如食盐和海盐）可设「库存计入」另一种原料：照常按自己的包装和价格进货，收货时算进那种原料的库存，配方和缺货只看那一种；原料可设「计库存」开关，关掉的（如水）不提示缺货、生产不扣库存、不进进货建议；进货单（草稿 → 已下单 → 收货入库）；原料可设「每袋多少」（如面粉 40 kg/袋），进货单按袋填数量、按袋填价格，系统自动换算成 kg 和每 kg 单价保存；低于最低库存的原料一键生成进货单；收货时填批号和保质期，并更新原料成本；收货后可直接打印进货标签（原料名、批号、入库日、到期日、供应商、每张数量、记录人、「开封：____」空行），每种原料可设印几张（默认一袋一张），已入库的进货单也能补打 |
| 标签打印 | 默认「简洁」样式，同 OkoHACCP 的内容：品名、Azon（批号，多张时加 -01/-02）、Rögzítő（记录人）、Gyártás időp.、Fogyasztható（到分钟）、Mennyiség（每张数量），可选加印 Tárolás（储存条件）和生产商名称地址（默认印）；二维码可选（默认不印）；可选加印营养成分表（每 100 g，数值在产品里填，长行自动换行）。所有标签（生产、分装、进货）共用一个纸张尺寸，默认 62 mm 连续纸 (DK-22205)、长 31.5 mm，文字自动放大到刚好占满。**手机**：点打印 → 分享菜单里选「打印」→ Brother QL-810W，用 iPhone 自带打印打 300 dpi 图片（iPhone 两端各留约 4.5 mm 白边，已按此加长标签）。**电脑**：打开精确尺寸的 PDF 打印（待电脑装好驱动后再调）。另有「完整」样式：配料表（过敏原加粗，包装不印）、生产商、储存条件等 |
| 原料配料名 | 原料可填配料表名称（匈/英/中，如「búzaliszt (BL80)」「savanyúságot szabályozó anyag (E500)」），产品信息、送货单配料都用它 |
| Slack 推送 | 「通知」页可打开 Slack 推送：每张新订单（客户、送货日、产品数量、净价合计、备注、后台链接）和每次取消订单发到一个 Slack 频道，语言可选；用 Slack Incoming Webhook，URL 放在 Supabase Edge Function Secrets 的 `SLACK_WEBHOOK_URL`；有「发测试消息」按钮，发送记录和邮件记录在一起 |
| 操作记录 | 管理员菜单「操作记录」：数据库触发器记录 17 张业务表的每次新建/修改/删除（谁、什么时候、旧值 → 新值），通过任何页面或 RPC 的改动都会记；用户在界面上遇到的错误和网页脚本错误也会记（`log_client_error`，同一条一分钟最多一次，每人 10 分钟最多 30 条）。可按时间、操作、对象、用户筛选和搜索，点一行看详情。只有管理员能读，没人能改或删 |
| 多门店客户 | 客户 = 公司（价格、价格分档、开票），公司下可加多个门店（`customer_locations`：送货地址、联系人、电话、送货日、送货备注）。门店送货日不填就跟公司一样。有门店的公司下单必须选门店（`place_order` 的 `p_location_id`）。账号可以是公司账号（能给所有门店下单、看全部订单），也可以在「账号」页限定到某个门店（只能给这个店下单、只看这个店的订单，数据库 RLS 控制）。订单列表、送货单、送货卡片、订单邮件、Slack 都显示门店名和门店地址 |
| 一个账号多个客户 | 下单账号可以关联多个客户（`profile_customers`），比如一位员工同时给自家餐厅和一个外部客户下单。在「账号」页点「再关联一个客户」添加，× 去掉。下单页顶部「正在为谁下单」切换（`switch_customer()`），切换后价格、订单记录、送货日、起订量都按那个客户算，角色自动跟着客户类型变（自家餐厅 / 外部客户）。订单邮件发给所有关联了这个客户的账号 |
| 修改 / 部分取消 / 拆分订单 | 后台点开订单（送达前）：「修改 / 部分取消」改数量或「取消这项」去掉某个产品（全部去掉 = 整单取消），价格不变；「拆分订单」勾选产品 + 新送货日 → 变成一张新订单（`split_from`，不重发新订单邮件）。外部客户在「我的订单」里，订单还在「待确认」时可以 ✕ 取消单个产品；自家餐厅在工厂排生产之前（这个产品还没有在下单之后、送货日之前排过生产批次）可以改数量、取消产品或整单取消，排了生产的产品显示 🔒。每次修改都进操作记录，Slack 收到「订单已修改」；整张单也能「改送货日期」（会从原来的送货趟移出） |
| 标签设置 | 「Címke beállítások」页：每个产品的保质期（天）和每张标签默认数量（kg），以及没填时用的默认值；打印时自动带出，数量默认按 kg |
| 订单邮件 | 用 Resend 从 noodle@101bistro.hu 发信：外部客户下单 →「已收到」，工厂确认 →「已确认」（员工代下单直接发「已确认」）；每个新订单给工厂发提醒；自家餐厅不收客户邮件。「E-mail beállítások」页可切换 关闭/测试/正式、改通知地址，并查看发送记录。数据库触发器 → Edge Function `noodle-order-email`（`supabase/functions/`）→ Resend；需要在 Supabase Edge Function Secrets 里设 `RESEND_API_KEY` |
| 下单规则 | 截单时间（布达佩斯时间）、提前天数、工厂送货日；匈牙利法定假日自动不送货（含复活节/圣灵降临节等移动假日和 12 月 24–26 日，每年自动算，`hu_holidays()`），调休日（áthelyezett pihenőnap）可选，日期每年按政府公告填；另外可手动加休息日，设置页列出接下来不送货的日子；每个客户可再限定送货日。客户下单页只显示能选的送货日，服务器也会检查；员工代下单不受限制 |
| 紧急订单 | 下单时点「🚨 紧急订单」可以选不是送货日的日子（工厂送货日、客户/门店自己的送货日都不限；截单时间、提前天数和休息日照样有效）。紧急订单一律要工厂确认，自家餐厅也一样；订单、送货页和 Slack / 工厂邮件都标「紧急」。「下单规则」页可设：所有客户 / 只限自家餐厅 / 关闭 |
| 报表 | 按时间段：产量、生产损耗（理论 vs 实际）、按客户/产品销售额、原料用量和成本、进货、报损；每张表可下载 CSV |
| 生产损耗 | 每个产品设「预计损耗 %」：生产计划和单位成本按预计产量（每批产量 × (1 − 损耗%)）算；完成生产时显示理论产量、预计产量和本批实际损耗，生产列表每批显示损耗 %，明显高于预计时标红 |
| 合规 / 法律页面 | 公开页面（不用登录）`/legal/impresszum`、`/legal/aszf`（B2B 交易条款：仅限企业、净价 + ÁFA、转账付款、质量问题当天反馈、补货或退款）、`/legal/adatvedelem`（GDPR 隐私政策：数据、法律依据、保存期限、Supabase/Vercel/Resend、NAIH）；匈语为准，附英文。公司信息在「下单与批号规则」页由管理员填写。外部客户申请账号和下单前须勾选接受条款（记录版本和时间，`accept_terms()`），条款版本号一改需重新接受，数据库 `place_order` 也会检查。客户下单页每个产品可展开「产品信息」：配料（过敏原加粗）、过敏原、净含量、储存条件、保质期、生产商；价格旁标「nettó」 |
| 手机桌面 | 可「添加到主屏幕」像 app 一样打开（iPhone 用 Safari 分享菜单，安卓/电脑直接点安装）|
| 批次追溯 | 扫标签二维码打开 `/trace/批号`：生产时间、产量、保质期、所用原料及生产前最近一次进货批号 |
| 产品与配方 | 产品三语名称、图片、规格、保质期、标准价（产品图片也显示在客户下单页）；每批用料配方，自动算每批成本、单位成本、毛利率 |
| 原料 / 供应商 | 基础资料，原料带过敏原，可上传图片（手机可直接拍照，自动压缩到 1200 px）；名称三语，常用分类（面粉、淀粉、辅料、蛋、包装…）按界面语言显示，也可自己写新分类 |
| 价格分档 | 管理员建档位（如 A/B 级批发），表格里给每个产品填档位价；客户选档位。价格规则：客户专属价 > 档位价 > 标准价，下单、客户下单页、员工代下单、送货页统一由数据库函数 `price_for` 计算；只有管理员能改档位价和客户的档位 |
| 客户 | 自家餐厅 / 外部批发；每个客户可设专属价格（管理员）；可关联拉面馆名单 `sales.ramen_leads` 的 place_id |
| 账号 | 管理员开通账号、设角色、把客户账号对应到客户；可以直接「添加账号」（邮箱 + 初始密码，建好就能登录，不用审批）和删除账号。登录账号和 order-app、配方 app 共用：只用于面坊的账号会被彻底删除，其他 app 也在用的只移除面坊权限。不能删自己和最后一个管理员。服务器函数 `noodle-admin-users` |

**客户门户**（手机优先）：客户登录后只能看到可订产品和自己的价格，下单、看历史订单、新订单可自行取消、一键再来一单。不含付款（货到后开发票）。

## 权限

- `admin` 全部，包括账号和客户价格
- `staff` 工厂日常工作
- `restaurant`（内部餐厅）只能给自己那家餐厅下单；看不到价格，不受最小起订量限制，下单直接算已确认
- `customer`（外部客户）只看自己的客户资料、价格和订单；价格由服务器决定，客户无法改价或替别人下单
- `pending` 刚注册，什么都看不到，等管理员开通

所有扣库存的操作（收货、完成生产、送达）都在数据库函数里一次完成，不会出现只扣一半的情况。

## 部署步骤

1. **建表**：Supabase → SQL Editor，运行 `supabase/001_noodle_schema.sql`
2. **开放 schema**：Settings → API → Exposed schemas，加上 `noodle`（和之前的 `ordering` 一样）
3. 依次运行 `supabase/003_restaurant_role.sql`、`005_default_hungarian.sql`、`006_delivery_proof.sql`、`007_delivery_proof_storage.sql`、`008_settings.sql`、`009_material_on_label.sql`、`010_label_defaults.sql`、`011_images.sql`、`012_order_emails.sql`、`013_lots_rules.sql`、`014_admin_users.sql`、`015_price_tiers.sql`、`016_compliance.sql`、`017_hu_holidays.sql`、`018_slack.sql`、`019_audit_log.sql`、`020_locations.sql`、`021_timeclock.sql`（已由 `024_remove_timeclock.sql` 撤销）、`023_multi_customer_accounts.sql`、`025_order_changes.sql`、`026_internal_order_edits.sql`
4. （可选）运行 `supabase/002_demo_data.sql` 装演示数据，文件底部有一键删除的 SQL
5. **本地运行**：
   ```
   copy .env.example .env      （填入 anon key，和 order-app 用的一样）
   npm install
   npm run dev
   ```
6. **第一个管理员**：在系统里注册并提交申请，然后在 SQL Editor 运行：
   ```sql
   update noodle.profiles set role = 'admin'
   where user_id = (select id from auth.users where email = '你的邮箱');
   ```
7. **上线**：推到 GitHub，Vercel 导入，环境变量填 `VITE_SUPABASE_URL` 和 `VITE_SUPABASE_ANON_KEY`（`vercel.json` 已配好路由）

> 注册要不要邮箱确认，取决于 Supabase → Authentication 的设置，和 order-app 共用同一设置。

## 开通内部餐厅账号

1. 在「客户」里建好餐厅，类型选「自家餐厅」
2. 餐厅员工注册并提交申请
3. 在「账号」里把角色设为「内部餐厅」，选对应的餐厅

## 开通外部客户

1. 在「客户」里建好客户（自家餐厅或外部批发），需要的话设专属价格
2. 让对方打开网址注册，填姓名、公司、电话提交
3. 在「账号」里把他设为「外部客户」，并选对应的客户
